# card-drag-sort 规范

## 目的
卡片拖拽排序与排序持久化功能。

## 需求
### 需求:卡片排序持久化
系统必须将用户设定的热榜卡片排列顺序持久化到浏览器本地存储，数据刷新时必须保持用户设定的顺序不变。

#### 场景:首次访问默认排序
- **当** 用户首次访问首页，本地无保存的排序记录
- **那么** 系统必须按 API 返回的默认顺序展示卡片

#### 场景:刷新数据保持顺序
- **当** 页面自动刷新或重新加载数据
- **那么** 系统必须按本地存储的顺序排列卡片，禁止因数据刷新导致卡片位置变化

#### 场景:新数据源追加到末尾
- **当** API 返回了本地排序记录中不存在的新数据源
- **那么** 系统必须将新数据源的卡片追加到已有排序的末尾

#### 场景:已删除数据源的清理
- **当** API 返回的数据源列表中不再包含某个已保存的数据源
- **那么** 系统必须从排序记录中自动移除该数据源标识

### 需求:拖拽排序交互
系统必须支持用户通过拖拽操作调整热榜卡片的排列顺序，拖拽必须通过专用拖拽手柄触发。

#### 场景:通过手柄拖拽卡片
- **当** 用户按住卡片标题栏中的拖拽手柄图标并拖动
- **那么** 系统必须显示拖拽视觉反馈（原位半透明占位），并允许用户将卡片放置到目标位置

#### 场景:拖拽完成后保存顺序
- **当** 用户完成一次拖拽操作（释放鼠标/触控）
- **那么** 系统必须立即将新的排列顺序保存到本地存储

#### 场景:拖拽手柄的视觉呈现
- **当** 卡片正常显示时
- **那么** 卡片标题栏右侧必须显示拖拽手柄图标，鼠标悬停时光标必须变为 grab 样式

#### 场景:分类筛选下的拖拽
- **当** 用户在分类筛选状态下（如选中"科技"）拖拽卡片
- **那么** 系统必须更新该卡片在全局排序中的位置，切换回"全部"分类时必须反映最新顺序
