## 需求
### 需求:简报列表页面
系统必须提供 `/briefings` 前端页面，展示所有简报。

#### 场景:简报列表展示
- **当** 用户访问简报页面时
- **那么** 必须展示简报列表，每条显示标题、类型标签、状态标签、生成时间，按时间倒序排列

#### 场景:类型和状态过滤
- **当** 用户选择类型或状态过滤器时
- **那么** 必须筛选并刷新列表

#### 场景:状态标签颜色
- **当** 展示简报状态时
- **那么** 必须用不同颜色区分：`done` 为绿色、`generating` 为蓝色/加载中、`failed` 为红色、`pending` 为灰色

### 需求:简报详情查看
系统必须在列表中支持点击查看简报详情。

#### 场景:Markdown渲染
- **当** 用户点击一份已完成的简报时
- **那么** 必须渲染其 Markdown 内容为 HTML 展示，包含标题、表格、列表等格式

#### 场景:引用来源展示
- **当** 简报有关联的热点条目时
- **那么** 必须在简报内容下方展示引用来源列表（标题+来源标签+链接）

#### 场景:生成中状态
- **当** 简报状态为 generating 时
- **那么** 必须显示加载指示器，并每 3 秒自动刷新直到状态变为 done 或 failed

### 需求:手动触发面板
系统必须在简报页面提供手动触发简报生成的面板。

#### 场景:选择生成类型
- **当** 用户使用触发面板时
- **那么** 必须可选择：单来源（下拉选来源）、每日汇总、主题（输入关键词+时间范围）

#### 场景:触发后反馈
- **当** 用户点击生成按钮后
- **那么** 必须在列表顶部显示新创建的简报记录（status=generating），并自动轮询更新

### 需求:导航栏入口
系统必须在导航栏中添加"简报"链接，指向 `/briefings` 页面。

#### 场景:导航可见
- **当** 用户在任何页面时
- **那么** 导航栏必须包含"简报"链接入口
