# briefing-share 规范

## 目的
待定 - 由归档变更 briefing-share-export 创建。归档后请更新目的。
## 需求
### 需求:创建分享链接
系统必须为指定简报生成一个随机 token 分享链接，用户可选择有效期（1天/7天/30天/永久），默认为7天。

#### 场景:首次分享简报
- **当** 用户对一篇未分享的已完成简报请求创建分享链接，选择有效期为7天
- **那么** 系统生成 32 字符 URL-safe token，存储到 briefing 记录，设置过期时间为当前时间 + 7 天，返回完整分享 URL 和过期时间

#### 场景:分享未完成简报
- **当** 用户对一篇状态为 pending/generating/failed 的简报请求创建分享链接
- **那么** 系统必须拒绝操作并返回错误提示

### 需求:更新分享有效期
系统必须允许用户在简报已分享状态下更新有效期，token 保持不变。

#### 场景:延长有效期
- **当** 用户对已分享的简报更新有效期为30天
- **那么** 系统保留原有 token 不变，将过期时间更新为当前时间 + 30 天，返回更新后的分享信息

#### 场景:改为永久有效
- **当** 用户将已分享简报的有效期更新为永久
- **那么** 系统保留 token，将 share_expires 设为 NULL，返回更新后的分享信息

### 需求:取消分享
系统必须允许用户取消简报的分享，清空 token 和过期时间，使旧链接永久失效。

#### 场景:取消已分享的简报
- **当** 用户对一篇已分享的简报执行取消分享操作
- **那么** 系统将 share_token 和 share_expires 设为 NULL，返回成功提示

#### 场景:取消未分享的简报
- **当** 用户对一篇未分享的简报执行取消分享操作
- **那么** 系统返回 404 错误

### 需求:公开访问分享链接
系统必须提供公开 API 端点，通过 token 获取简报内容，无需认证。

#### 场景:访问有效分享链接
- **当** 访问者使用有效且未过期的 token 访问分享端点
- **那么** 系统返回简报的标题、类型、生成时间、Markdown 内容和引用来源列表

#### 场景:访问过期分享链接
- **当** 访问者使用已过期的 token 访问分享端点
- **那么** 系统返回 410 Gone 状态码及"链接已过期"提示

#### 场景:访问无效 token
- **当** 访问者使用不存在的 token 访问分享端点
- **那么** 系统返回 404 Not Found 状态码

### 需求:分享阅读页面
系统必须提供独立的分享阅读页面，展示简报内容，使用报告式排版。

#### 场景:正常打开分享页面
- **当** 访问者通过浏览器打开有效的分享链接
- **那么** 页面以报告式布局展示简报（最大宽度 720px、居中、正文 16px、行高 1.8），使用固定浅色主题，底部展示 "Powered by NewsHub" 及链接回主站

#### 场景:打开过期或失效链接
- **当** 访问者打开已过期或已取消的分享链接
- **那么** 页面显示友好的"此简报链接已失效"提示，底部仍展示 NewsHub 品牌

### 需求:分享管理交互
详情 modal 中必须提供分享管理入口，支持创建分享、查看链接、复制链接、更新有效期和取消分享。

#### 场景:未分享状态显示分享按钮
- **当** 用户打开已完成简报的详情 modal
- **那么** 显示"分享"按钮，点击后弹出分享对话框，包含有效期选择（1天/7天/30天/永久，默认7天）

#### 场景:已分享状态显示管理界面
- **当** 用户打开已分享简报的详情 modal 并点击"分享"
- **那么** 分享对话框直接展示已有链接和复制按钮、有效期信息、"更新有效期"选项和"取消分享"按钮

### 需求:简报列表分享状态标识
简报列表中必须标识已分享的简报。

#### 场景:列表展示分享标识
- **当** 简报列表加载
- **那么** 已分享且有效的简报在标题旁显示分享图标/标签
