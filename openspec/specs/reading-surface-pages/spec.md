## 需求
### 需求:统一阅读型页面体验
系统必须将首页、搜索、历史、分享页和简报阅读态组织为统一的前台阅读表面，并使用一致的信息层级和内容组件。

#### 场景:页面遵循统一阅读节奏
- **当** 用户在前台内容页面之间切换
- **那么** 系统必须保持一致的标题层级、内容宽度、来源标识、时间信息和空状态呈现方式

### 需求:首页作为内容主入口
系统必须将首页呈现为面向内容发现的主入口，而不是后台功能卡片面板。

#### 场景:首页展示热点内容层次
- **当** 用户访问首页
- **那么** 系统必须优先展示热点条目、来源信息、热度与更新时间，并以阅读导向的内容布局替代纯工具型网格卡片观感

#### 场景:首页保留分类浏览
- **当** 用户切换内容分类或频道
- **那么** 系统必须在不破坏阅读节奏的前提下更新展示范围，并保持来源卡片或条目列表的可扫描性

### 需求:搜索与历史页面阅读化
系统必须将搜索页和历史页呈现为内容发现与回看页面，而不是仅提供表单和结果块的操作界面。

#### 场景:搜索结果可阅读扫描
- **当** 用户执行关键词搜索
- **那么** 系统必须以统一的阅读型结果条目展示来源、标题、时间和热度等关键信息

#### 场景:历史记录支持继续浏览
- **当** 用户查看历史页面
- **那么** 系统必须以便于回看和继续阅读的方式组织已读或历史条目，而不是仅展示原始数据列表

### 需求:分享页与简报详情作为阅读终点
系统必须将分享页和简报阅读态呈现为低噪声、适合长内容阅读和传播的页面。

#### 场景:分享页公开阅读
- **当** 用户访问有效分享链接
- **那么** 系统必须以独立阅读页面展示标题、正文和引用来源，并禁止暴露后台管理控件

#### 场景:简报详情适配长内容阅读
- **当** 用户查看简报正文
- **那么** 系统必须以阅读优先的排版展示 Markdown 内容、引用来源和相关操作，而不是将其限制在后台式详情弹窗中
