## 需求
### 需求:热榜列表查询接口
系统必须提供 RESTful API 接口，支持查询当前各平台的热榜数据。接口必须支持按来源和分类过滤。

#### 场景:查询全部热榜
- **当** 客户端请求 `GET /api/hot` 且不带过滤参数
- **那么** 系统必须返回所有来源的最新一轮热榜数据，按来源分组

#### 场景:按来源查询
- **当** 客户端请求 `GET /api/hot/{source}`（如 `/api/hot/weibo`）
- **那么** 系统必须仅返回该来源的最新热榜条目列表，按排名升序排列

#### 场景:按分类查询
- **当** 客户端请求 `GET /api/hot?category=科技`
- **那么** 系统必须返回该分类下所有来源的最新热榜数据

### 需求:分页支持
所有返回列表的 API 必须支持分页参数 `page` 和 `page_size`，默认每页 20 条。

#### 场景:分页查询
- **当** 客户端请求 `GET /api/hot/zhihu?page=2&page_size=10`
- **那么** 系统必须返回第 2 页的 10 条知乎热榜数据，响应中必须包含总条数 `total` 和当前页码

### 需求:数据源元信息接口
系统必须提供接口返回所有已配置数据源的元信息，包括名称、显示名称、分类、最后采集时间和采集状态。

#### 场景:获取所有数据源信息
- **当** 客户端请求 `GET /api/sources`
- **那么** 系统必须返回所有已配置数据源的列表，每项包含 `name`、`display_name`、`category`、`last_collected_at`、`status` 字段

### 需求:API 文档自动生成
系统必须利用 FastAPI 的内置能力自动生成 Swagger/OpenAPI 文档。

#### 场景:访问 API 文档
- **当** 用户访问 `/docs`
- **那么** 系统必须展示完整的交互式 API 文档，包含所有端点的请求参数和响应格式说明
