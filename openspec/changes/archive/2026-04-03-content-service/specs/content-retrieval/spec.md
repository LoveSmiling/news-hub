## 新增需求

### 需求:按条件检索热点内容
系统必须提供 `retrieve_contents(...)` 异步函数，按多维条件从数据库检索热点条目并返回清洗后的内容。

#### 场景:按来源检索
- **当** 调用时指定 `source="hackernews"`
- **那么** 必须仅返回该来源的条目，每条包含 `id`, `title`, `source`, `url`, `content`（清洗后纯文本）, `collected_at`

#### 场景:按时间范围检索
- **当** 调用时指定 `start_time` 和/或 `end_time`
- **那么** 必须仅返回 `collected_at` 在指定时间范围内的条目

#### 场景:按关键词过滤
- **当** 调用时指定 `keyword="AI"`
- **那么** 必须仅返回标题中包含该关键词（不区分大小写），或 `keywords` JSONB 数组中包含该关键词的条目

#### 场景:按条目ID列表检索
- **当** 调用时指定 `item_ids=[1, 2, 3]`
- **那么** 必须仅返回指定 ID 的条目

#### 场景:内容自动清洗
- **当** 返回条目时
- **那么** `content` 字段必须是从 `raw_data->>'summary'` 提取并经过 HTML 清洗后的纯文本

#### 场景:内容自动截断
- **当** 调用时指定 `max_content_chars=2000`
- **那么** 每条返回的 `content` 必须经过截断处理，不超过指定字符数

#### 场景:限制返回数量
- **当** 调用时指定 `limit=50`
- **那么** 必须最多返回 50 条结果，按 `collected_at` 降序排列

#### 场景:无匹配结果
- **当** 查询条件无匹配的条目
- **那么** 必须返回空列表，禁止抛出异常

### 需求:返回数据结构
检索结果必须以 `ContentItem` 数据类（dataclass 或 TypedDict）返回，字段包括：`id: int`, `title: str`, `source: str`, `url: str`, `content: str`, `collected_at: datetime`。

#### 场景:字段完整性
- **当** 检索到条目
- **那么** 每个 `ContentItem` 的所有字段必须有值，`content` 为清洗后文本（如原始内容为空则为空字符串）
