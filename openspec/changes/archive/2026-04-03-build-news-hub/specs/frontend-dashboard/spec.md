## 新增需求

### 需求:热榜卡片式展示
前端必须以卡片网格布局展示各平台的热榜数据，每个平台对应一个独立的卡片，卡片内按排名列出热榜条目。

#### 场景:首页加载展示
- **当** 用户访问首页
- **那么** 页面必须展示所有已配置数据源的热榜卡片，每张卡片显示来源名称、条目列表（标题+热度值）和最近更新时间

#### 场景:点击条目跳转
- **当** 用户点击某条热榜条目
- **那么** 系统必须在新标签页中打开该条目的原始链接

### 需求:分类标签页浏览
前端必须提供分类标签页（综合、科技、娱乐、社区、开发等），用户点击标签页后仅展示该分类下的数据源卡片。

#### 场景:切换分类
- **当** 用户点击"科技"标签页
- **那么** 页面必须仅展示分类为"科技"的数据源卡片（如 36氪、IT之家、HackerNews 等）

#### 场景:默认展示全部
- **当** 用户首次访问页面
- **那么** 页面必须默认选中"全部"标签页，展示所有分类的数据源卡片

### 需求:暗黑模式
前端必须支持亮色和暗黑两种主题模式，用户可手动切换，且系统必须记住用户的偏好。

#### 场景:切换暗黑模式
- **当** 用户点击主题切换按钮
- **那么** 页面必须立即切换为暗黑/亮色主题，所有组件颜色同步变化

#### 场景:记住主题偏好
- **当** 用户设置暗黑模式后关闭页面再重新访问
- **那么** 页面必须自动应用用户上次选择的主题模式

### 需求:自动刷新
前端必须定时从 API 拉取最新数据并更新卡片内容，无需用户手动刷新页面。

#### 场景:定时自动更新
- **当** 页面已展示热榜数据且经过设定的刷新间隔时间
- **那么** 页面必须自动请求最新数据并平滑更新卡片内容，禁止全页面刷新导致闪烁

### 需求:响应式布局
前端必须适配不同屏幕尺寸，在桌面端展示多列卡片，在窄屏/移动端自动调整为少列或单列布局。

#### 场景:桌面端多列展示
- **当** 浏览器窗口宽度大于 1200px
- **那么** 页面必须以 3-4 列网格布局展示卡片

#### 场景:移动端适配
- **当** 浏览器窗口宽度小于 768px
- **那么** 页面必须以单列布局展示卡片，卡片宽度撑满屏幕
