## 上下文

当前前端把内容消费入口和后台管理入口都放在同一套顶栏布局下。首页、搜索、分享和简报详情等内容页面使用与设置、日志、知识库、源管理相同的导航密度和组件风格，导致用户在浏览热点、阅读简报和执行后台操作时无法形成稳定的界面预期。现有代码也主要依赖单一的 AppLayout 和一组直接面向业务页的 Naive UI 组件组合，缺少可复用的壳层、设计令牌和页面类型边界。

本次变更的约束是：不改变后端接口，不推翻现有路由，不强制更换前端框架；允许在现有 Vue 3 + Vite + Naive UI 之上增加新的布局壳、共享样式层和定制内容组件。相关利益方包括内容消费用户、运营使用者以及后续维护前端页面的一线开发者。

## 目标 / 非目标

**目标：**
- 将前端拆分为前台阅读壳和后台工具壳两种页面模式。
- 为前台页面建立统一的品牌表达、阅读节奏和响应式规则。
- 为后台页面保留效率优先的工作台属性，同时统一到同一套设计令牌体系。
- 在不改变现有业务能力的前提下，重新定义首页、搜索、历史、分享页和简报阅读态的页面角色。
- 建立可以支持后续页面持续演进的壳层与组件边界。

**非目标：**
- 不在本次设计中修改后端 API、数据库结构或权限模型。
- 不要求一次性重写所有前端组件，也不要求全面替换 Naive UI。
- 不在本次变更中引入新的内容推荐算法、搜索语义能力或简报生成逻辑。
- 不追求让后台工具页完全复制前台阅读风格。

## 决策

### 决策 1：采用双壳结构，而不是继续在单一布局上堆条件分支

前台页面与后台页面在导航密度、标题节奏、背景氛围、内容容器宽度和交互噪声控制上存在根本差异。继续在单一 AppLayout 上通过 if/else 切换样式，会让布局逻辑和业务页耦合越来越深。双壳结构允许通过路由元信息显式声明页面归属，并把前台阅读体验和后台工作台体验的责任边界固定下来。

备选方案：
- 保留单壳，仅通过主题变量换肤：改造成本低，但无法解决导航密度和页面定位冲突。
- 为每个页面独立定制头部：局部灵活，但长期会造成样式分叉和组件重复。

### 决策 2：保留 Naive UI 作为后台控件基础，前台内容组件转为定制化实现

后台页仍以表单、列表、弹窗、提示和状态管理为主，这些部分继续使用 Naive UI 成本最低。前台页面如果继续以 n-card、n-tabs、n-list 为主要视觉骨架，则很难达到阅读产品的完成度。因此设计上采用“后台沿用组件库、前台自建内容组件”的混合策略。

备选方案：
- 全站彻底去 Naive UI：视觉控制更强，但重构成本过高，且会拖慢后台页面改造。
- 全站继续依赖 Naive UI 主题覆盖：实现快，但前台页面只能停留在组件库换皮层面。

### 决策 3：先建立共享设计令牌，再推进页面分期改造

如果首页、搜索、分享页各自独立改样式，后续很容易出现字体、圆角、阴影、状态色和间距重新发散。共享设计令牌应先定义主色、文本层级、背景层级、边框透明度、阅读排版、间距尺度和动效节奏，再由前台壳和后台壳共同引用。

备选方案：
- 每个页面局部定义 scoped CSS：初期快，但后期维护成本高。
- 完全依赖第三方 utility 体系默认 token：可用，但不能准确表达产品自身的品牌边界。

### 决策 4：把首页、搜索、历史、分享页和简报阅读态归入统一前台阅读面

这些页面承担“发现内容、筛选内容、回看内容、阅读内容、传播内容”的连续链路，适合被看作同一阅读表面。简报列表管理态仍然保留后台属性，但简报详情应升级为阅读态入口，以减少后台弹窗承担长内容阅读的负担。

备选方案：
- 仅首页做风格改造：见效快，但整体产品体验仍然割裂。
- 所有页面都归前台：会牺牲设置、日志、知识库、源管理等页面的效率。

## 风险 / 权衡

- 路由与布局归属判断过于粗糙 → 通过显式 route meta.layout 声明前台、后台和最小壳，而不是依赖路径约定。
- 前台页面定制组件增多，维护成本上升 → 通过共享内容组件和设计令牌收束重复实现。
- 后台页面风格改动过大影响操作效率 → 后台仅做壳层和视觉统一，不重写核心操作流。
- 首页改造后与现有组件库视觉割裂 → 让后台页继续保留组件库风格，同时保证基础色板、圆角和间距来自同一套令牌。
- 前台阅读体验过重，导致移动端信息密度下降 → 在设计中优先定义移动端收缩策略、内容截断规则和频道导航折叠方式。

## 迁移计划

1. 为路由增加布局元信息，允许页面在前台壳、后台壳和最小壳之间切换。
2. 引入共享设计令牌层，并先接入 App 级布局与全局背景样式。
3. 优先重构首页及其热榜展示组件，验证前台阅读壳的视觉语言。
4. 在前台壳下逐步吸纳搜索、历史、分享页和简报阅读态。
5. 再统一后台工具页的容器、导航和层级样式，确保整体品牌一致性。
6. 保留回滚能力：每个页面可单独切回后台壳或旧组件，不影响后端接口与数据模型。

## 开放问题

- 是否需要引入新的 utility CSS 方案来支撑前台页面开发，还是先基于现有样式体系构建令牌层。
- 简报详情是否应从弹窗迁移为独立路由页，还是在短期内提供阅读式详情面板作为过渡。
- 趋势页和推荐页的产品定位是否足够清晰，能否在第二期明确归入前台或后台。
- 前台壳是否需要保留对深色/浅色主题切换的用户控制，还是默认以单一主风格呈现。
